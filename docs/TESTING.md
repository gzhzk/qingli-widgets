# 独立环境验收清单（尚未执行）

本轮做了静态核验和合成文件升级测试；下面是真实Rainmeter运行环境中的待执行步骤，不是通过报告。使用独立官方 Rainmeter 环境，不能覆盖或加载到正在使用的同名皮肤环境。

1. 记录 Windows、Rainmeter、PowerShell 版本和DPI；核对程序来源及签名、Skins与配置目录属于独立环境，使用普通用户权限。
2. 默认 OpenMeteo 下无需 QWeather.local.json。加载 Start/Start.ini，应出现两卡；检查经典红、缩放0.9、六行日历、周一开头、同排农历、温度单位和来源链接。
3. AutoIP 成功后检查城市级估计；失败无缓存时不得把广州示例当作真实城市。检查手动刷新、15分钟天气及1小时定位的真实请求周期，记录实际证据，不能以修改时间戳冒充等待。
4. 预先切换 Manual 并填写合法示例坐标，检查无IP定位请求、城市点击刷新天气。测试错误枚举、空城市、越界坐标时应报配置错误。不要在共享报告中保留自己的精确位置或IP。
5. 若有自己的和风产品权限，按 QWEATHER.md 配置，验证 PowerShell 子进程是固定助手、输出为JSON、凭据不在命令行或主动日志中，来源正确，当前天气15分钟、预报1小时。没有凭据或无法联网时应标“未验证”。
6. 验证和风忙碌/冷却/完成提示与手动10秒节流；OpenMeteo 不承诺同样的反馈。检查同坐标刷新、来源切换和定位失败后保留位置的行为。
7. 检查翻月、返回今天、跨日农历、六行月份和100%/150%/175%等DPI；确认来源署名字体颜色可辨、点击链接正确。
8. 验证配色预设、自定义面板收起、材质切换、重启保留；只在隔离副本测试缓存断网和保存失败、.bak恢复。勿通过更改系统代理、权限或生产文件来凑测试通过。
9. 退出独立Rainmeter实例后确认该实例组件和隐藏助手停止；确认没有增加开机启动。再次加载Start会重新排列两卡，属于预期行为。
10. 分享测试结果前清理凭据、坐标、IP、缓存和日志；输出通过/失败/未验证及可复查证据，不沿用历史版本通过数字。
